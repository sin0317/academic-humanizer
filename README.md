# academic-humanizer：学术论文去 AI 味

学术论文专用。把 AI 辅助写出来的论文改回能过同行评审的样子：句子清楚，声音是作者自己的，每个主张都挂得住证据——而数字、公式、引文一个没动。

## 这个技能解决什么

通用的"去 AI 味"工具是为博客和营销写的。把它们丢给一篇论文或一份基金申请书，精确性会跟着 AI 腔一起被铲平：该保留的对冲被删，该保留的术语被换，"the results suggest X" 被改成 "the results prove X"（这是在**制造**过度主张）。

本技能是两套方法论的合并：

| 来源 | 提供什么 | 用在哪 |
|---|---|---|
| [AIScientists-Dev/academic-humanizer](https://github.com/AIScientists-Dev/academic-humanizer) v0.3.3 | 英文学术六层法：通用 AI-tell → 学术 tells → 保留学术惯例 → claim↔evidence → 声音与期刊匹配 → NSF/NIH 申请书模式 | 英文期刊会议稿、rebuttal、基金申请 |
| humanizer-zh-pro v1.4.10 | 中文 A–Z 规则 + 知网/万方/维普/朱雀四档实测校准 + 三平台 AI 率预估的强制流程 | 中文学位论文、中文期刊稿 |

## 用法

```
/academic-humanizer
[贴一段，或指向 main.tex / 论文.docx]
# 可选：目标期刊用知网检测；这是我的已发表稿，照这个声音改
```

三个典型入口：

- **中文论文**："帮我把这篇硕士论文的摘要和结论去 AI 味，学校用万方检测，已有报告：结论段标红 62%。"
- **英文论文**："Humanize the related work and introduction. Target venue ICLR. Keep every citation."
- **基金申请**："润色 NSF Project Summary，愿景别删，但每个大胆主张都要有落脚点。"

## 整合时改了什么

不是把两个 SKILL.md 拼起来就完事。五处实质改动：

1. **中文规则从字母表重排为按段落功能组织**（摘要/综述/理论/方法/结果/结论/通用）。作者改稿时手里拿的是一节一节的内容，不是一个词表。原字母号保留在括注里，方便和校准档案对照。
2. **补全通用模式**。原技能"通用内容模式 24 类"里有 6 类初版漏了，其中"挑战与未来展望"提纲腔、"虚假范围"在论文引言与结论里很常见——已补成 §4.8（12 条 + 3 条对话残留）。
3. **新增冲突消解表**。两套方法论有三处直接冲突，已定档：要不要"注入个性与观点"（学术稿不注入）、破折号（英文删净/中文每千字 ≤2）、补数据降 AI 率（只能补真实数据）。
4. **给"补数据降 AI 率"加了硬约束**。原中文规则 P 说"抽象处补年份、地名、数字"最有效——放在学术稿里这是伪造数据的入口。现在限定为"只能补原稿已有或作者提供的真实数据，无数据可补时改为降级主张"。
5. **检测器校准证据移入 references/**。主文件只留决策表（哪个平台清什么、留什么），避免每次调用都吞掉几十 KB。

## 两个反直觉的结论（值得先知道）

- **有数据 ≠ 安全。** 同一篇数据密度 31.7% 的统计稿，BestPaper 78.15%、朱雀 82.51%、论文狗正文 71.08%。被标的不是数据，是数据外面那层"优/高/中/低四并列 + %""①②③ 枚举""三对称"。同一篇里数据更密但展开成叙述的段落，朱雀只给 0.2560。**拆包裹，不删数据。**
- **检测器结论不可混用。** 同一篇论文，知网 3% vs 维普 67%（差 64 点）；同一篇算法定义密集硕论，万方 56% vs 知网 21%。送审用哪款，就按哪款的标注片段改，别拿另一个平台的"20% 通过"安慰自己。

## 边界

不做公文、月报、公众号与营销文案（那些走 `humanizer-zh-pro` / `human-writing`）。不生成观点，不编数据，不改公式与引文。**不承诺"绕过 AI 检测"**——它做特征清理，但作者对 AI 使用的披露义务不因此消失，投稿前按目标期刊与学校的政策声明。
